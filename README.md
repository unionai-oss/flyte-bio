# flyte-bio

The [Flyte 2](https://www.union.ai/docs/v2/flyte/) open-source library for
biology.

flyte-bio gives you, and the AI agents you build, nearly 900 scientific tools
as typed Python functions: sequence alignment, variant calling, single-cell
and spatial transcriptomics, proteomics, metagenomics, imaging and more. Each
tool runs in its own pinned container on your Flyte cluster, with caching,
retries and lineage, so a workflow written by a scientist or generated by an
agent is reproducible from the first run.

- **Tools** (`flyte_bio.modules`): about 900 tools in 400+ families
  (samtools, BWA, GATK, STAR, salmon, Cell Ranger, MultiQC, …). Each is an
  async function with typed `File`/`Dir` inputs and outputs, and nearly all are
  tested against known-good outputs.
- **Workflows** (`flyte_bio.pipelines`): end-to-end analyses composed from
  those tools: bulk RNA-seq quantification, single-cell RNA-seq and germline
  variant calling.

## Install

flyte-bio isn't on PyPI yet. Install it from GitHub:

```bash
uv add "flyte-bio @ https://github.com/unionai-oss/flyte-bio/archive/refs/heads/main.zip"
```

It needs `flyte>=2.13.1`. Two extras configure workflows from YAML files
([configuring a run](docs/pipelines/README.md#configuring-a-run-with-a-file)):
`flyte-bio[config]` in your task's image, and `flyte-bio[hydra]` where you
launch runs with `flyte hydra run`.

## Usage

Your code runs in your own Flyte task, which calls the flyte-bio tools. That
needs two things:

- **flyte-bio installed in your task's image**, because your task imports it.
  The tool containers don't need it.
- **A `depends_on` on the flyte-bio environments**, so running or deploying
  your task also registers every tool and its container. `flyte_bio.env`
  covers all of them.

```python
import flyte

from flyte_bio import env as bio_env

FLYTE_BIO = "flyte-bio @ https://github.com/unionai-oss/flyte-bio/archive/refs/heads/main.zip"

env = flyte.TaskEnvironment(
    name="my_analysis",
    image=flyte.Image.from_debian_base().with_pip_packages(FLYTE_BIO),
    resources=flyte.Resources(cpu=2, memory="4Gi"),
    depends_on=[bio_env],
)
```

### Call a tool

Tools are ordinary async calls inside your task:

```python
from flyte.io import File

from flyte_bio.modules.bedtools import bedtools_intersect


@env.task
async def overlaps(annotation: File, peaks: list[File]) -> File:
    return await bedtools_intersect(a=annotation, b=peaks, wa=True, f=0.5)
```

To give a tool more CPU or memory for one call, override its task:
`await tool.override(resources=flyte.Resources(cpu=8, memory="32Gi"))(...)`.
The tool's thread and memory options follow the resources it gets.

### Run a workflow

A workflow takes a samplesheet CSV and can publish its results as a folder
tree:

```python
from flyte.io import Dir, File

from flyte_bio.pipelines.rnaseq import rnaseq


@env.task
async def quantify(samplesheet: File, fasta: File, gtf: File, outdir: str | None = None) -> Dir:
    result = await rnaseq(samplesheet, fasta=fasta, gtf=gtf, outdir=outdir, publish_results=True)
    return result.outdir
```

```bash
flyte run my_analysis.py quantify --samplesheet samples.csv --fasta genome.fa --gtf genes.gtf
```

[`examples/`](examples/) has a complete, runnable script for each workflow.

## For agents

flyte-bio is built to be driven by coding and research agents:

- **Find a tool** in the [tool catalog](docs/modules.md#available-modules):
  one row per family, with what it does and its function names. Each tool's
  module docstring documents its inputs, outputs and file names.
- **Call it** with typed Python: `File` and `Dir` for data, plain values for
  options, and small dataclasses for multi-output tools. A call is easy to
  generate and type-check.
- **Compose freely.** A tool's output is a valid input to the next tool,
  and Flyte caches every step, so iterating on a workflow reruns only what
  changed.
- **Mind licences.** Tools under restrictive licences (vendor EULAs,
  non-commercial terms) say so in the catalog and live in
  `flyte_bio.modules.licensed_env`, which `flyte_bio.env` leaves out. Depend
  on it explicitly once the terms are checked.

[`docs/agents.md`](docs/agents.md) is the quick reference to load into an
agent's context.
